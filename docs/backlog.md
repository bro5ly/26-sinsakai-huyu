## 進め方

- **動きを変えない整理**(`refactor:`): 先に今の動きを確かめるテストを書いて緑にし、緑のまま形を変える
- **動きを変える修正**(`fix:`・`feat:`): 仕様の表に行を足してから、赤 → 緑 → 整える。緑になるたびに1コミット
- 判断は副作用(DB・時計・乱数・トークン・メール)の無い関数に出し、テストはその関数に対して書く。DBに触る部分は薄くする
- **実装を優先し、テストもClaudeが書く**(2026-10-23に変更。それまでは開発者が書く決まりだった)。大体の機能ができたら、最後のほうの機能だけ開発者が練習としてテストを書く(2026-10-30に、今は考えないことにした。5のINV13)
- **まとめて決める(2026-10-29、開発者の希望。例外)**: 0.8のf〜「2. 登録・ログイン」は、判断の要る所を1つの表で先にまとめて聞き、決まったら止まらずに進める(CLAUDE.mdの「1つずつ」の例外)。
  - **X1** まとまり(f → g → 0.7の残り → 2)ごとに、クラウドでテスト・型チェック・ビルドを通してPRを出し、`main`にマージして次へ進む。Macでの確かめは最後にまとめて行い、見つかった不具合は別のPRで直す
  - **X2** マイグレーションのSQLは止まらずに作り、最後の報告で中身を見せる(DBに入れるのは開発者がMacで流すとき)。ただし、ある行を消す・書き換えるSQLになったら、そこで止まる
  - **X3** 開発者が練習としてテストを書くのは今回は無し。在庫管理(5)でする → 2026-10-30に、在庫管理でも今は考えないことにした(5のINV13)
  - **S1**(2026-10-29、開発者が選んだ) 開発のときの認証コードは、`docker compose`のMailpit(http://localhost:8025)で見る。コードをハッシュで持つようにし、Prisma Studioで見られなくなったため。アカウントが要らず、コードがログに残らない(ブランチ`chore/mailpit`)
- **クラウドとMacの分担**(2026-10-24決定): Dockerの無いクラウドのセッションでは、テスト・型チェック・画面のビルドまでを確かめて、コミットとpushをする。PRを`main`に入れる前に、開発者のMacで`docker compose up -d --build -V api`・`npm test`・`curl`(ログイン・カード認証・貸し出し・返却)を確かめる。同じ確認を繰り返したくなったら、CI(下の0の項目)にする
