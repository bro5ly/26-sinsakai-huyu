# 生徒カード貸し出し管理システム 要件定義

このシステムが「何を満たすべきか」をまとめたもの。実装の仕組みは`docs/architecture.md`、過去の経緯は`REFACTORING_PROGRESS.md`。

各要件の「状態」は2026-10-23時点のコードを読んで付けた: ✅ 実装済み / △ 一部 / — 未実装。

## 1. 目的と背景

学校で配られている生徒カード(学生証)は、身分証明以外にほとんど使われていない。このカードを使って、**機材や本の貸し出し・返却を、カードをかざしてバーコードを読むだけで終わらせる**。

**ICチップについての前提**: 今の生徒カードには、実際にはICチップは付いていない。このシステムは**将来カードにICチップが付く想定**で作っている。それまでは、カードの番号(シリアル番号)をバーコードで読むか手で入力して、ICの読み取りの代わりにする。カードの番号の読み方が変わっても、タブレットが受け取るのは「カードの番号」なので、API(`POST /api/tablet/signin`)は変えずに済む。

成功の目安:
- 貸し出し1件が、カードをかざしてから30秒以内に終わる
- 誰が・何を・いつまで借りているかを、紙の台帳なしで確かめられる
- 学生が自分の借りている物と返却期限を、自分で確かめられる

## 2. 範囲

**やること**
- タブレット(貸し出し受付の端末)での、カードによる本人確認と、貸し出し・返却
- 学生向けWebサイトでの、登録・ログイン・借りている物の確認・機材カタログの閲覧
- 登録時のメールによる本人確認

**あとでやること**(既存のリファクタと修正が終わってから。要件は`docs/inventory.md`に書く)
- 在庫管理: 物品の種類と物品の追加・編集(状態を修理中・紛失などに変えることを含む)。それまでは物品をseedかPrisma Studioで入れる

**やらないこと(今回は作らない)**
- 貸し出しの統計、延滞者の管理
- 予約
- Slackやメールでの返却期限の通知(テーブル`notification`だけ用意してある)
- モバイルアプリ
- 学校の本物の名簿・ICカードとの連携(`ExternalUser`とシリアル番号の手入力・バーコードで代用)。ただし**本番の名簿は学校のDBかAPIを読む前提**で作る(2026-10-23決定)。名簿の読み方は1か所(名簿の窓口)にまとめ、差し替えられるようにする

## 3. 利用者と流れ

| 利用者 | 使う場所 | すること |
|---|---|---|
| 学生(`STUDENT`) | タブレット・Webサイト | 借りる・返す・自分の状況を見る |
| 教職員(`FACULTY`) | 同上 | 学生と同じ(権限の違いは未定。要確認Q4) |
| 管理者(`ADMIN`) | (未実装) | 物品と利用者の管理 |

**ユーザーストーリー**
- 学生として、カードをかざすだけで機材を借りたい。名前や学籍番号を書く手間を省くために
- 学生として、自分が何をいつまでに返せばよいかをスマホで見たい。返し忘れないために
- 学生として、借りたい機材が今空いているかを見たい。無駄に取りに行かないために
- 管理者として、誰が何を借りているかを台帳なしで知りたい。紛失を防ぐために

### 3.1 タブレットでの貸し出し・返却

1. 生徒カードをかざす(ICチップは将来付く想定。今はカードの番号をバーコードで読むか入力する)
2. 本人確認ができたら、名前と今借りている物の一覧が出る
3. 「貸し出し」か「返却」を選ぶ
4. 物品のバーコードをカメラかバーコードリーダーで読む(手入力もできる)
5. 完了の表示が出て、一定時間で最初の画面に戻る

### 3.2 Webサイトの新規登録

1. 学籍番号を入力する
2. 名簿に登録されたメールアドレスに6桁の認証コードが届く
3. 認証コードを入力する
4. パスワード(8文字以上)を決める
5. 登録が終わり、ログインした状態でダッシュボードに入る

### 3.3 ログイン後

- **ダッシュボード**: 自分の情報(名前・学籍番号・学年・専攻)、自分のカードのバーコード、借りている物と返却期限
- **機材カタログ**: 全物品の一覧、カテゴリ・ジャンルでの絞り込み、貸し出しできるかどうか
- **物品の詳細**: 説明・メーカー・型番・貸し出し期間・在庫数・今の貸し出し状況

## 4. 用語

| 用語 | 意味 |
|---|---|
| 名簿 | 学校が持つ学生・教職員の一覧。試作では`ExternalUser`テーブルで代用 |
| シリアル番号 | 生徒カードの番号。ICチップが付いたら、その番号を読む想定。今はバーコードか手入力。タブレットでの本人確認に使う |
| 物品の種類 | 同じ本・同じ型の機材のまとまり(`ItemType`)。貸し出し期間を持つ |
| 物品 | 種類の中の1つ1つ(`Item`)。バーコードを1つ持つ |
| 貸し出し | 1人が1つの物品を借りた記録(`Rental`) |
| 貸し出し期間 | 物品の種類ごとの日数。返却期限 = 貸し出した日時 + 日数 |

## 6. 判断表: 貸し出せるか

条件が結果に関係しないところは「—」。上から順に見て、最初に当てはまった行の結果になる。

| # | 物品がある | 物品の状態 | 利用者が貸し出し可能 | 停止期間中 | 借りている数 < 上限 | 結果 | 状態 |
|---|---|---|---|---|---|---|---|
| C1 | いいえ | — | — | — | — | 断る(404 物品が見つかりません) | ✅ |
| C2 | はい | 貸出中 | — | — | — | 断る(409 貸し出し中の物品です) | ✅ |
| C3 | はい | 修理中・紛失・廃棄 | — | — | — | 断る(400 貸し出し不可能な物品です) | ✅ |
| C4 | はい | 貸し出し可能 | いいえ | — | — | 断る(貸し出しが止められています) | — |
| C5 | はい | 貸し出し可能 | はい | はい | — | 断る(〜まで貸し出しが止められています) | — |
| C6 | はい | 貸し出し可能 | はい | いいえ | — | 断る(返却期限を過ぎた物があります)※延滞中の物があるとき | — |
| C7 | はい | 貸し出し可能 | はい | いいえ | いいえ | 断る(借りられる数の上限です) | — |
| C8 | はい | 貸し出し可能 | はい | いいえ | はい | 貸し出す(物品は貸出中、返却期限 = 今 + 期間) | ✅ |

- 「利用者が貸し出し可能」「停止期間」「上限」は`user`の`canBorrow`・`suspendedUntil`・`maxItems`(上限の初期値5。Q5)
- 延滞中 = 返却されておらず、返却期限が今より前の貸し出しが1件以上ある。`status`の`OVERDUE`ではなく期限から判断する(`OVERDUE`にする処理が無いため)。延滞者には貸さない(Q6、2026-10-23決定)

## 7. 非機能要件

| 観点 | 要件 | 状態 |
|---|---|---|
| 性能 | タブレットの各操作(カード・バーコード)は1秒以内に応答する(校内の数十台・数百人規模) | 未計測 |
| 同時操作 | 同じ物品を2台のタブレットで同時に借りようとしても、貸し出しは1件だけになる | ✅ 部分インデックス(返却されていない貸し出しは物1つにつき1件)で守る。2件目は409 |
| 認証 | アクセストークン・リフレッシュトークン・登録用トークン・タブレット用トークンは、それぞれ別の秘密鍵か別の用途の印で区別し、互いに使い回せない | — (現状とのずれ2・3) |
| 権限 | 利用者は自分の情報と自分の貸し出しだけを見られる | ✅ |
| 名簿の差し替え | 名簿を同じDBの表から学校のDB・APIに変えても、変えるのは名簿の窓口の実装1つだけで済む。名簿の情報(名前・メール・カードの番号)をこのシステムのDBに写さない | — 外部キーとJOINで名簿の表に直接つながっている(現状とのずれ12) |
| 個人情報 | 名前・学籍番号・シリアル番号をサーバーやブラウザのログに出さない | — 動作確認用のログが残っている(現状とのずれ5) |
| 秘密情報 | 秘密鍵・メールのパスワード・DBの接続情報は`.env`に置き、コミットしない | ✅ |
| 総当たり | 認証コード・ログインは、続けて失敗したら止める | — |
| 運用 | `docker compose up -d`だけで、画面・API・DB・Prisma Studioが起動する | ✅ |
| 対応端末 | タブレットの画面はiPadの横向き、学生向けはスマホの縦向きでも崩れない | 未確認 |

| Q7 | 卒業・退学した人の情報と貸し出しの記録をいつ消すか | 名簿から消えた人は、貸し出し中の物が無ければ無効(`isActive = false`)にし、記録は1年残す |
| Q8 | メールの送信元の名前 | 「機材貸し出しシステム」 |
| Q9 | 1人が複数の端末で同時にログインできるようにするか | できるようにする(リフレッシュトークンを端末ごとに持つ) |
| Q10 | カードを忘れた人が、ダッシュボードのバーコードでタブレットを使ってよいか | よい(R-28のとおり)。画面の写しの使い回しを防ぐなら、時間で変わるコードにする |
