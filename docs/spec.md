# 生徒カード貸し出し管理システム 要件定義

このシステムが「何を満たすべきか」をまとめたもの。実装の仕組みは`docs/architecture.md`、過去の経緯は`REFACTORING_PROGRESS.md`。

各要件の「状態」は2026-10-23にコードを読んで付け、作り直しのたびに直している(最後に全体を見直したのは2026-10-30): ✅ 実装済み / △ 一部 / — 未実装。

## 1. 目的と背景

学校で配られている生徒カード(学生証)は、身分証明以外にほとんど使われていない。このカードを使って、**機材や本の貸し出し・返却を、カードをかざしてバーコードを読むだけで終わらせる**。

**ICチップについての前提**: 今の生徒カードには、実際にはICチップは付いていない。このシステムは**将来カードにICチップが付く想定**で作っている。それまでは、カードの番号(シリアル番号)をバーコードで読むか手で入力して、ICの読み取りの代わりにする。カードの番号の読み方が変わっても、タブレットが受け取るのは「カードの番号」なので、API(`POST /api/tablet/sessions`の`cardNumber`)は変えずに済む。

成功の目安:
- 貸し出し1件が、カードをかざしてから30秒以内に終わる
- 誰が・何を・いつまで借りているかを、紙の台帳なしで確かめられる
- 学生が自分の借りている物と返却期限を、自分で確かめられる

## 2. 範囲

**やること**
- タブレット(貸し出し受付の端末)での、カードによる本人確認と、貸し出し・返却
- 学生向けWebサイトでの、登録・ログイン・パスワードの再設定・借りている物の確認・機材カタログの閲覧
- 登録とパスワードの再設定のときのメールによる本人確認
- 認証の作り直し(タブレットの端末の登録、カードの番号 + PIN、短いセッション。`docs/auth.md`)

**あとでやること**(既存のリファクタと修正が終わってから。要件は`docs/inventory.md`に書く)
- 在庫管理: 物品の種類と物品の追加・編集、状態を修理中・紛失などに変える(貸出中の物を紛失にすることも含む)、誰が何を借りているかの一覧、利用者の貸し出しを止める・上限を変える。それまでは物品をseedかPrisma Studioで入れる
- Slackでの返却期限の通知(期限が近い・過ぎた)。在庫管理より後(テーブル`notification`だけ用意してある)

**やらないこと(今回は作らない)**
- 貸し出しの統計
- 予約
- 返却期限の延長
- 利用者からの破損・紛失の届け出(管理者に直接伝え、管理者が紛失にする)
- メールでの返却期限の通知
- モバイルアプリ
- 学校の本物の名簿・ICカードとの連携(`ExternalUser`とシリアル番号の手入力・バーコードで代用)。ただし**本番の名簿は学校のDBかAPIを読む前提**で作る(2026-10-23決定)。名簿の読み方は1か所(名簿の窓口)にまとめ、差し替えられるようにする

**ユーザーストーリー**
- 学生として、カードをかざすだけで機材を借りたい。名前や学籍番号を書く手間を省くために
- 学生として、自分が何をいつまでに返せばよいかをスマホで見たい。返し忘れないために
- 学生として、借りたい機材が今空いているかを見たい。無駄に取りに行かないために
- 学生として、カードを人に見られても勝手に借りられたくない。身に覚えのない貸し出しで止められないために
- 管理者として、誰が何を借りているかを台帳なしで知りたい。紛失を防ぐために

### 3.3 詳しいユースケース

判断の分かれ目があるものだけ、流れと例外まで書く。例外は**結果が変わるものだけ**で、判断表の行とテストの元になる。ボタンの名前・画面の色・APIやテーブルの名前は書かない。**下の流れは`docs/auth.md`の叩き台(端末の登録・PIN)が入った後の形**で、今の作りとの違いは「今」に書く。

#### UC-8 タブレットで借りる

- **利用者**: 学生・教職員
- **前提**: タブレットが端末として登録されている(UC-20)。利用者がWebでPINを登録している(UC-7)
- **主な流れ**
  1. 利用者がカードの番号を読ませる(ICチップは将来付く想定。今はバーコードか手入力)
  2. 利用者がPINを入力する
  3. タブレットが、利用者の名前を出す(借りている物は出さない。後ろに並ぶ人にも見えるため。ダッシュボードで見る。2026-10-30 A2)
  4. 利用者が「借りる」を選び、物品のバーコードを読ませる
  5. タブレットが、借りた物と返却期限を出す
  6. 利用者が「終わる」を押す(または完了の表示から10秒たつ)と、最初の画面に戻る
- **例外の流れ**
  - 1〜2: 端末が登録されていない → 断る(T1)
  - 2: カードが名簿に無い・無効・PINが違う・PIN未登録 → 「カードかPINが違います」(T2・T3・T5。どれかは言わない)
  - 2: PINを5回続けて間違えた → PINをロックし、Webで再設定するまで断る(T4)
  - 4: 物品が無い・修理中など・貸出中 → 断る(C1〜C3)
  - 4: 貸し出しが止められている・停止期間中・延滞中・上限に達している → 断る(C4〜C7)
  - 3〜5: 30秒操作が無い、または始めてから3分たった → セッションを切り、最初の画面に戻る
- **終わったあと**: 貸し出しの記録ができ、物品が貸出中になる。セッションは無効
- **今**: 端末・カード + PIN・30秒/3分/10秒/「終わる」は2026-10-29に作った。判断表CはC1〜C8すべて(C4〜C7は0.8のe2)。完了の表示から10秒の間は、同じセッションで続けて操作できる(R-A10・2026-10-30 B3)

#### UC-9 タブレットで返す

- **利用者**: 誰でも(借りた本人でなくてよい。Q3)
- **前提**: タブレットが端末として登録されている
- **主な流れ**
  1. 利用者が「返す」を選ぶ
  2. 利用者が物品のバーコードを読ませる
  3. タブレットが、返した物を出し、数秒で最初の画面に戻る
- **例外の流れ**
  - 1: 端末が登録されていない → 断る
  - 2: その物品の貸出中の記録が無い → 「この物品は貸し出されていません」(R-23)
- **終わったあと**: 貸し出しの記録に返却日時と、返却を受け付けた端末が入る
- **今**: 2026-10-29から、登録された端末で、カード無しで返せる(最初の画面の「返す」)

#### UC-1 Webで新規登録する

- **利用者**: 名簿にいて、まだ登録していない学生・教職員
- **主な流れ**
  1. 利用者が学籍番号を入力する
  2. システムが、名簿のメールアドレスに6桁の認証コードを送る(15分有効)
  3. 利用者が認証コードを入力する
  4. 利用者がパスワード(8文字以上)を決める
  5. 登録が終わり、ログインした状態でダッシュボードに入る
- **例外の流れ**
  - 1: 名簿に無い・登録済み → 画面は2と同じ「登録できる学籍番号なら、メールを送りました」(列挙の対策。`docs/auth.md`4.6)
  - 1: 同じ学籍番号でもう一度申請した → 新しいコードを送り、古いコードは無効(R-5)。1分に1回・1時間に5回まで
  - 3: コードが違う → 断る。同じコードで5回間違えたらそのコードを無効にする(R-8)
  - 3: 期限切れ → 断り、再申請を案内する
- **終わったあと**: 利用者ができる(名簿の項目は写さない)。Webのセッションの番号がCookieに入る
- **今**: すべて満たす(再申請・5回で無効・申請の回数は2026-10-29。名簿に無い・登録済みを応答で分からなくしたのは2026-10-24)

#### UC-20 タブレットの端末を登録する・取り消す

- **利用者**: 管理者
- **主な流れ(登録)**
  1. 管理者が、置くタブレットでタブレットのページを開く
  2. 管理者が、管理者の学籍番号とパスワードでログインする
  3. 管理者が端末の名前(例: 図書室入口)を付けて登録する
  4. タブレットが受付の画面になる。管理者のログインはここで終わる
- **主な流れ(取り消し)**
  1. 管理者がWebで端末の一覧を開き、取り消す端末を選ぶ
  2. その端末は、次の操作から断られる
- **例外の流れ**
  - 2: 管理者でない → 断る
- **終わったあと**: 端末の番号がタブレットのCookieにだけ入り、DBにはハッシュだけが残る
- **今**: 2026-10-29に作った(登録は`POST /api/tablet-devices`、取り消しは`/admin/tablets`)

## 4. 用語

| 用語 | 意味 |
|---|---|
| 名簿 | 学校が持つ学生・教職員の一覧。試作では`ExternalUser`テーブルで代用 |
| シリアル番号 | 生徒カードの番号。ICチップが付いたら、その番号を読む想定。今はバーコードか手入力。タブレットでの本人確認に使う |
| 物品の種類 | 同じ本・同じ型の機材のまとまり(`ItemType`)。貸し出し期間を持つ |
| 物品 | 種類の中の1つ1つ(`Item`)。バーコードを1つ持つ |
| 貸し出し | 1人が1つの物品を借りた記録(`Rental`) |
| 貸し出し期間 | 物品の種類ごとの日数。返却期限 = 貸し出した日時 + 日数 |
