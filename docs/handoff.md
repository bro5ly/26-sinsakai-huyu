> 引き継ぎを読みました。私の理解は次のとおりです。違うところがあれば教えてください。
>
> 1. **進め方**: まとめて進めず、問題を1つずつ出し、修正案と論点を番号付きの表(選択肢・おすすめと理由)にして、あなたに選んでもらう。決まったことは`docs/`に日付と番号付きで残してから次へ進む。作業の前に触るファイルと理由を見せ、作業の後にテストなどの結果を見せて止まる。答えの無い質問は実装の前に聞き直すが、返事から読み取れることは聞き直さない。文書や決まりを直すときは、同じことを書いている古い記述をすべて探して直す
> 2. **テスト**: 実装を優先し、テストも私が書く(赤 → 緑 → 整える)。テストは関数ごとの`describe`の中を正常系・異常系・境界値に分け、名前に仕様の番号を入れる。最後のほうの機能だけ、あなたが練習としてテストを書く
> 3. **今いる所**: 0.7の「組み立てとrouteの作り直し」(PR #9)と「npm workspacesと`shared/`」(PR #11)は済み(2026-10-24)。0.7の「APIを新しいURLに移す」の途中で、登録・ログインの6本(PR #13)と本人の2本を移した(2026-10-25)。次はカタログ。`buildDeps(config)`(本物の部品を作る)・`createApp(deps, config)`(部品と設定で Express の app を組み立てる)・`create○○Routes(deps)`・`route()`(入力の検証とログインの確認を受け持つ)の役割と型の書き方は、前のセッションで説明して理解してもらった
> 4. **進め方の決まり**: 区切りごとに、前に予定・後に結果を見せて止まる。確認せずに直したもの(文書など)も、後でまとめて見せる。クラウドではテスト・型チェック・画面のビルドまでを確かめてコミットとpushをし、PRを`main`に入れる前にあなたのMacで`curl`などを確かめる。Macに貼るコマンドには`#`のコメントを付けない(zshでは引数になってしまう)
> 5. **大事な決まり**: 失敗の応答はRFC 9457の形で、エラー用のミドルウェアだけが返す。serviceは`DomainError(code)`を投げる(`code`は`shared/src/error-codes.ts`の表のものだけ)。判断の関数は`{ ok: false, reason }`を返す。名簿は名簿の窓口(`Roster`)からだけ読む
> 6. **環境**: 私の環境ではDockerが使えないかもしれない。その場合、テストと型チェックはコンテナを使わずに動かし、`curl`やブラウザでの確認はできないので、そのことを毎回はっきり書く
>
> この理解で合っていれば、3章のとおり、次の作業の進め方を決めるところから始めます。

## 5. 環境の注意

**Dockerが使えるとき(開発者のMac)**: `CLAUDE.md`の「コマンド」のとおり、コマンドはコンテナの中で動かす。`curl`で確かめる前に、`docker compose logs api`で再起動を確かめる。環境変数が足りないと、APIは起動のときに`環境変数が足りないか、形が違います: ○○`と出して止まる(seedも同じ)。workspacesにしたとき(2026-10-24)に`node_modules`の場所が変わったので、その前のコンテナが残っていたら、`docker compose down`のあとに`docker compose up -d --build -V`で作り直す

**Dockerが使えないとき(クラウドなど)**:
- リポジトリの直下で`npm ci`のあと(workspacesなので直下で1回)、`back/`で`npx vitest run`と`npx tsc --noEmit`はDB無しで動く(テストは偽の部品を使う)。Node 22以上が要る(Vitest 5)
- **テストはJWTの鍵を環境変数から読む**。`back/.env`が無いと、トークンを作るテストが落ちる。`cp back/.env.example back/.env`のあと、`JWT_ACCESS_SECRET`と`JWT_REFRESH_SECRET`に適当な長い文字列(別々の値)を入れる(`.env`はコミットしない)
- テストは`vitest.config.ts`の`setupFiles`で`back/.env`を読む(2026-10-24 D1)。`cd back && npx vitest run`だけで動く
- `src/generated/prisma/`はコミットしてあるので、`prisma generate`は要らない(スキーマを変えたら要る)
- DBとAPIのサーバーは動かせないので、`curl`・ブラウザでの確認・マイグレーションの適用はできない。できなかったことは、報告とこのファイルに書き、開発者のMacで確かめてもらう

**知っておくこと**:
- `prisma migrate dev`は対話が要るので、自動では動かない。マイグレーションは`prisma migrate diff --from-config-datasource --to-schema prisma/schema.prisma --script`でSQLを作り、開発者に見せてから`prisma migrate deploy`で入れる(前回、Prismaが出したSQLの順番を手で直したことがある)
- APIのイメージにOpenSSLが無く、Prismaの道具が警告を出す。今は動いている。後回しで、ブランチ`fix/api-image-openssl`を切ってある(手元だけ)
- 新しいnpmは、インストール時のスクリプトを許可制にしている(prisma・bcrypt・esbuildなどは止められているが、今は無くても動く)
- テスト用のデータ: ログイン`20240001`/`password123`(管理者`90240001`)、カード`IC-CARD-001`〜`003`、物品`MAC-002`など(`MAC-001`は貸出中、`IPAD-005`は修理中)
