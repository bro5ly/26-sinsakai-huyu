# 認証の作り直し 要件と方針

タブレット(公共の場に置く)と、学籍番号・カードの番号の扱いを見直す。全体の要件は`docs/spec.md`、今の仕組みは`docs/architecture.md`の「認証とトークン」。

2026-10-23に、今のコードとAPIを確かめて書いた。**要確認A-Q1〜A-Q8は、2026-10-23に叩き台どおりに決定した。**

## 1. 目的と背景

今のタブレットの認証は、次の状態になっている(確かめた結果)。

- カードの番号(シリアル番号)だけで本人確認する。カードの番号はバーコードで誰でも読め、写真でも写せる。ダッシュボードにも同じバーコードが出る
- タブレットの端末を確かめていない。`/api/tablet/*`はどこからでも呼べるので、カードの番号が分かれば学校の外から他人の名前で借りた記録を作れる
- カード認証の応答に名前・学籍番号・学年・専攻・借りている物が入る。回数の制限もないので、番号を順に試せば個人情報を集められる
- タブレットのトークンは3分のJWTで、取り消せない。画面は無操作1分で戻り、完了画面から「続けて操作」できる。立ち去ると次の人が前の人の名前で借りられる
- Webのアクセストークンでタブレットの貸し出しが通る(鍵が同じで、`role`を見ていない)
- 無効にした人(`is_active = false`)も認証できる
- ログイン・認証コードに失敗の回数の制限がない。学籍番号が名簿にあるか・登録済みかが、応答の違いで分かる

成功の目安: **カードの写しだけでは借りられない。学校の外からは借りられない。立ち去った人の名前で次の人が借りられない。**

## 2. JWTとサーバーのセッションの使い分け

| | JWT(署名付きトークン) | サーバーのセッション(推測できない乱数の番号をDBに持つ) |
|---|---|---|
| 確かめ方 | 署名と期限を見るだけ。DBを見なくてよい | 毎回DBで探す |
| 期限前に取り消す | できない(取り消すにはDBに黒リストが要り、JWTの良さが消える) | 行を消せばすぐ無効 |
| 向いているもの | 短命で、取り消せなくても困らないもの。複数のサービスで同じトークンを確かめたいとき | 取り消しが要るもの。1回使ったら終わりにしたいもの |

方針:
- **タブレットの本人確認のセッションは、サーバーのセッションにする**(JWTをやめる)。1回の操作で終わらせたい・立ち去ったらすぐ無効にしたい・端末と結び付けたいので、取り消せることが一番大事
- **タブレットの端末の登録も、サーバーのセッションと同じ形**(管理者が取り消せる)
- Webのアクセストークン(15分)はJWTのままでよい。リフレッシュトークンはもともとDBに持っているので、ハッシュにして保存する
- 登録用トークン(15分)はJWTのままでよい。ただし用途を分ける(5章)
- 作り: `crypto.randomBytes(32)`で番号を作り、DBにはハッシュ(SHA-256)だけを持つ。Expressのセッションのライブラリ(`express-session`)は使わない(タブレットはヘッダーで渡し、表1つで足りるため)

## 3. 学籍番号とカードの番号の区別

| | 学籍番号 | カードの番号(シリアル番号) | 利用者のID(`user.id`) |
|---|---|---|---|
| 何か | **誰か**を表す名前。学校が決め、変わらない | **持ち物**(カード)の番号。カードを無くすと変わる | このシステムの中だけの番号(UUID) |
| 秘密か | 秘密ではない(名簿・名札・提出物に書く) | **半分秘密**として扱う(見せない・記録に出さない) | 秘密ではないが、画面に出さない |
| 使い道 | Webのログインの「ID」、名簿を引く鍵 | タブレットで「カードを持っている」ことを示す | テーブルどうしのつながり、トークンの`sub` |
| 単独で本人確認に使うか | **使わない**(パスワードと組にする) | **使わない**(PINと組にする。A-Q3) | 使わない |
| 画面・APIの応答に出すか | 本人のダッシュボードだけ | **出さない**(ダッシュボードのバーコードもやめる。A-Q6) | 出さない |
| ログに出すか | 出さない | 出さない | 出してよい(調べるとき用) |
| 持ち主 | 名簿(学校) | 名簿(学校)。カードの交換は名簿の更新で反映する | このシステム |

## 4. 修正案

### 4.1 タブレットの端末を登録する(タブレットのページ自体の認証)

- **R-A1** 管理者がタブレットで管理者のIDとパスワードでログインし「この端末を登録」すると、システムは端末用の番号を発行し、HttpOnly Cookieでその端末に持たせる。DBには端末の名前・ハッシュ・登録した人・最後に使った日時を持つ
- **R-A2** `/api/tablet/*`は、登録された端末の番号が無ければ、どれも401で断る
- **R-A3** 管理者は、端末の登録を取り消せる(盗まれた・使わなくなったとき)。取り消した端末は次の呼び出しから断る
- **R-A4** (任意)学校のネットワークからだけ受け付ける設定を持てる(A-Q2)

### 4.2 カードの番号 + PIN(サイト内で登録する暗証番号)

- **R-A5** 利用者は、Webでログインして、タブレット用のPIN(数字)を登録・変更できる。PINはbcryptのハッシュだけを保存する
- **R-A6** タブレットで借りるときは、カードの番号を読んだあとにPINを入力する。PINを登録していない人には「Webで先にPINを登録してください」と出し、借りさせない
- **R-A7** もしPINを続けて5回間違えたら、そのカードのタブレットでの認証を止め、Webでログインし直してPINを再設定するまで止めておく
- **返却はカード・PINを要らない**(返却は本人でなくてよいと決めた。Q3)。登録された端末であれば、物品のバーコードを読むだけで返却できる(A-Q4)

### 4.3 タブレットのセッションの期限

- **R-A8** カード + PINが通ったとき、システムはサーバーのセッション(上の2章の形)を作る。セッションは**その端末でだけ**使える
- **R-A9** セッションは、最後の操作から30秒で切れる。作ってから3分を超えたら、操作中でも切れる(A-Q5)
- **R-A10** 利用者が「終わる」を押したとき、または完了画面を出してから10秒たったとき、システムはセッションをすぐ無効にする
- **R-A11** セッションが切れたとき、タブレットは最初の画面に戻り「もう一度カードを読んでください」と出す(APIは`{ message, code }`のJSONで401を返す。ずれ4)

### 4.4 カード認証の応答から個人情報を外す

- **R-A12** カードの番号を送った時点の応答は「PINを入力してください」だけにする。カードが有効かどうかも、PINが通るまで分からないようにする(番号を順に試しても何も分からない)
- **R-A13** PINが通ったあとの応答は、画面に出すものだけにする: 表示用の名前と、借りている物の名前・返却期限・延滞かどうか。**学籍番号・学年・専攻・カードの番号・利用者のIDは返さない**

### 4.5 無効な人を通さない

- **R-A14** もし利用者が無効(`is_active = false`)・名簿にいない(Q13)なら、システムはWebのログイン・リフレッシュ・タブレットの認証を、どれも断る。理由はPINが通る前には言わない
- **R-A15** 貸し出しが止められている人(`can_borrow = false`・停止期間中・延滞中)は、認証は通るが、借りる操作は断る(判断表C4〜C6)

### 4.6 総当たりと列挙の対策

| 対象 | 対策(叩き台) |
|---|---|
| Webのログイン | 学籍番号ごとに続けて5回失敗したら15分止める。加えて、接続元(IP)ごとに15分で20回まで |
| 認証コード(登録) | 1つのコードで5回間違えたら、そのコードを無効にする(R-8)。再送は1分に1回、1時間に5回まで。コードはハッシュで保存し、比べるときは時間の差が出ない比べ方(`crypto.timingSafeEqual`)を使う |
| PIN(タブレット) | カードごとに5回でロック(R-A7)。端末ごとに1分で20回まで |
| カード認証 | 端末ごとに1分で20回まで(端末の登録で、そもそも外からは呼べない) |
| 列挙(学籍番号があるか・登録済みか) | 登録の申請は、あってもなくても「登録できる学籍番号なら、メールを送りました」と同じ応答にする。ログインの失敗は「学籍番号かパスワードが違います」だけにする(Q2・R-16) |

回数の数え方: 接続元ごとの制限は`express-rate-limit`(メモリ。1台のAPIなら足りる)、学籍番号・カードごとの失敗の回数はDBの列(`failed_attempts`・`locked_until`)に持つ。

### 4.7 トークンの用途を分ける(ずれ2・3)

- **R-A16** JWTは用途ごとに別の鍵で署名する(`JWT_ACCESS_SECRET`・`JWT_REFRESH_SECRET`・`JWT_REGISTRATION_SECRET`)。鍵を使い回さない
- **R-A17** すべてのJWTに用途の印(`typ: "access" | "refresh" | "registration"`)を入れ、確かめるときに印も確かめる。署名の方式は`HS256`に固定して確かめる(`algorithms: ["HS256"]`)
- **R-A18** タブレットのセッションはJWTをやめる(4.3)ので、Webのトークンとタブレットのトークンの取り違えは起きなくなる
- **R-A19** ログアウトしたとき、DBのリフレッシュトークンも消す(R-15、ずれ8)

## 5. 判断表: タブレットで借りられるか(T)

上から順に見て、最初に当てはまった行の結果になる。「—」は結果に関係しない。

| # | 登録された端末 | カードが名簿にある・有効 | PINを登録済み | PINがロック中 | PINが合う | 結果 |
|---|---|---|---|---|---|---|
| T1 | いいえ | — | — | — | — | 断る(401、端末が登録されていません) |
| T2 | はい | いいえ | — | — | — | 断る(「カードかPINが違います」。どちらかは言わない) |
| T3 | はい | はい | いいえ | — | — | 断る(Webで先にPINを登録してください) |
| T4 | はい | はい | はい | はい | — | 断る(PINがロックされています。Webで再設定してください) |
| T5 | はい | はい | はい | いいえ | いいえ | 断る(「カードかPINが違います」)。失敗を1回数え、5回目でロック |
| T6 | はい | はい | はい | いいえ | はい | セッションを作る(失敗の回数を0に戻す)。この後は判断表C(貸し出せるか)へ |

T2とT3は、PINを入れる前に答えを変えると「カードが有効か」が分かってしまう。**T3はカードとPINの両方が合ったあとに出す**か、PINの登録が無い人にも同じ「カードかPINが違います」を出すかは、A-Q3で決める。

## 6. 要確認

| # | 内容 | 決定(2026-10-23、叩き台どおり) |
|---|---|---|
| A-Q1 | タブレットの本人確認のセッションを、JWTからサーバーのセッションに変えるか | 変える(取り消せることが一番大事なため。2章) |
| A-Q2 | タブレットの端末をどう確かめるか | 管理者のログインで端末を登録する(R-A1〜A3)。学校のネットワークに限る設定は、本番の構成が決まってから足す |
| A-Q3 | カードの番号とは別に、PINを入れさせるか。何桁か | 入れさせる。数字4桁、5回でロック。PIN未登録の人にも、カードとPINが合うまでは「カードかPINが違います」を出す |
| A-Q4 | 返却にカード・PINが要るか | 要らない(登録された端末で物品のバーコードを読むだけ)。どの端末でいつ返したかは記録する |
| A-Q5 | タブレットのセッションの長さ | 無操作30秒、最長3分、完了画面は10秒で終わる、「終わる」で即時に無効 |
| A-Q6 | ダッシュボードのカードの番号のバーコードをどうするか(カードを忘れたとき用。Q10) | カードの番号は出さない。代わりに、ログイン中のスマホに**60秒で変わる使い捨てのバーコード**を出し、それをタブレットで読ませる(PINも入れる) |
| A-Q7 | 総当たりの回数と止める時間 | 4.6の表のとおり |
| A-Q8 | 名簿にいない・無効な人の扱い | 4.5のとおり(Q13と同じ) |

## 7. 変える場所(要件が決まってから)

- DB: `tablet_device`(端末)、`tablet_session`(本人確認のセッション)、`user`に`pin_hash`・`pin_failed_attempts`・`pin_locked_until`・`login_failed_attempts`・`login_locked_until`、`verification_codes`に`attempts`と用途(登録・パスワードの再設定。`docs/spec.md` R-36)、`refresh_tokens.token`をハッシュに
- API: `/api/tablet/*`の作り直し(端末の確認 → カード → PIN → セッション)、`/api/me/pin`(PINの登録)、`/api/admin/tablets`(端末の登録・取り消し)
- 画面: タブレットにPINの入力と端末の登録画面、ダッシュボードにPINの設定と使い捨てのバーコード
- 環境変数: `JWT_REGISTRATION_SECRET`を足す
